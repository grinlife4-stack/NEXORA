# Mandatory project-entry instructions

Before any work, read this file and the [Ecosystem Master Map](https://github.com/grinlife4-stack/TRADIX/blob/main/docs/ECOSYSTEM_MASTER_MAP.md). Then read this repository's README, NEXORA dossier, decision log, and current status.

NEXORA is an independent product/project, not a department or child of TRADIX. TRADIX may provide reusable production capabilities to NEXORA; this does not transfer NEXORA's ownership, roadmap, data, accounts, finances, users, or operational decisions. EXVARLI may provide reusable specialist financial-management capabilities; it must preserve NEXORA's separate financial perimeter and must not own or mix NEXORA's funds or ledger with another project.

NEXORA identifies and prioritizes its own needs. It may create a capability, extend an existing shared tool, or contribute one or more reusable tools/options to the shared toolbox. Other projects may use a contributed capability when it fits their needs, but adoption is optional and creates no hierarchy or merger. NEXORA is not required to build capabilities for every other project.

Keep NEXORA independently operable, exportable, and replaceable from shared services. A shared tool must not become a permanent dependency without explicit approval. Reusable contributions must not expose NEXORA-specific data, secrets, or private business logic without explicit authorization. Repository placement or source-import workflow does not change NEXORA's independent project boundary.

Before editing, confirm this repository, branch, scope, and the exact NEXORA source/status. If work crosses a boundary, define interfaces, data ownership, permissions, maintenance responsibility, and acceptance responsibilities first. If unclear, stop and report the ambiguity.
